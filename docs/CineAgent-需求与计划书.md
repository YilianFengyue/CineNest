# CineAgent — AI驱动的个性化影视推荐App

## 需求与开发计划书

---

## 一、项目概述

CineAgent 是一款 **AI Agent 驱动的个性化影视推荐与观影应用**。它不是传统的影视聚合器——用户打开 App 看到的不是千篇一律的电影列表，而是 **AI 根据你的口味动态生成的"帖子流"**，每一张帖子都是专属定制的 Micro Design 海报卡片，带推荐理由、评分、标签，点进去就能直接看电影或看 B站解说视频。

PC 端作为算力中心运行 FastAPI + LangChain Agent，负责影视数据采集、AI 推荐、视频源解析、海报生成；手机端（Flutter）是用户的主交互界面，负责展示、播放和 Agent 对话。

**一句话定位：AI 为你策展的私人影院入口。**

## 二、技术栈（推荐，不锁死实现）

### 手机端

| 层级 | 推荐方案 | 备选 | 说明 |
|------|---------|------|------|
| 框架 | Flutter | — | 一套代码出 Android + HarmonyOS |
| 状态管理 | GetX | Provider / Riverpod | GetX 上手最快，路由+状态+DI 一把梭，课设效率优先 |
| 网络请求 | Dio | http | Dio 拦截器、超时控制更完善 |
| 视频播放 | media_kit | chewie + video_player | media_kit 是 Kazumi/PiliPlus 系列验证过的方案，m3u8/mp4/flv 全支持 |
| 本地缓存 | Hive | shared_preferences | 存偏好/观影记录/缓存帖子 |
| WebView | flutter_inappwebview | webview_flutter | 视频播放降级方案 + B站网页播放兜底 |
| 图片缓存 | cached_network_image | — | 海报图加载与缓存 |

### PC端

| 层级 | 推荐方案 | 备选 | 说明 |
|------|---------|------|------|
| Web框架 | FastAPI | Flask | 异步、自动 Swagger 文档、类型安全 |
| AI框架 | LangChain + LangGraph | 直接调 LLM API | Agent 工具调用、链式推理 |
| LLM | DeepSeek API | Qwen API / OpenAI | 便宜好用，兼容 OpenAI 格式 |

| 数据库 | SQLite | PostgreSQL | 课设零部署成本 |
| 海报生成 | HTML模板 + 截图（playwright / imgkit） | Flutter 端直接渲染 | 由具体开发者选择最顺手的方案 |

## 三、功能清单与验收标准

> 每个功能都写清楚：**做什么 → 用户看到什么 → 怎么算完成**

### 🔴 MVP 核心功能（必须完成）

---

#### F1：AI 推荐帖子流（首页）

**功能描述**：
App 首页是一个由 AI Agent 动态生成的帖子卡片流。每张卡片展示一部电影/影视作品的推荐信息。帖子内容由 PC 端 Agent 根据用户偏好、影视热度、评分等综合生成，推送到手机端展示。

**帖子卡片包含的信息**：
- 电影海报图（来自 TMDB）
- 中文标题 + 英文标题
- 年份
- 类型标签（科幻、悬疑、动画...）
- 评分（TMDB 评分，可选豆瓣评分）
- AI 推荐理由（一句话，如"你喜欢烧脑反转，这部不会让你失望"）
- 是否有在线播放源的标识
- 是否有 B站解说视频的标识

**用户交互**：
- 上下滑动浏览帖子流
- 下拉刷新获取新一批推荐
- 点击卡片进入电影详情页

**验收标准**：
- [ ] 首页打开后 3 秒内展示至少 10 张帖子卡片
- [ ] 每张卡片完整展示上述所有信息字段
- [ ] 下拉刷新能获取新一批不重复的推荐
- [ ] 卡片布局美观，有加载骨架屏/占位动画
- [ ] 推荐内容与用户设置的偏好类型相关（不是随机的）

---

#### F2：电影详情页

**功能描述**：
从帖子卡片点击进入，展示一部电影的完整信息和可用的观看方式。

**页面包含**：
- 电影海报大图 + 背景模糊图
- 完整简介/剧情概要
- 导演、主演列表
- 评分信息
- AI 推荐理由（展开版，比卡片上更详细）
- 可用视频源列表（在线播放源，标明清晰度）
- B站相关视频列表（解说、混剪、影评等，展示标题+封面+播放量）
- "不感兴趣"/"喜欢"按钮（影响后续推荐）

**用户交互**：
- 点击视频源 → 进入播放器页面
- 点击 B站视频 → 进入播放器播放 / 跳转 B站 App
- 标记喜欢/不喜欢 → 反馈给 Agent 调整推荐

**验收标准**：
- [ ] 详情页信息完整，无空白字段
- [ ] 至少展示 1 种可用视频源（在线播放或 B站）
- [ ] B站相关视频搜索结果至少展示 3 条
- [ ] 喜欢/不喜欢的反馈能被后端接收并影响后续推荐结果

---

#### F3：视频播放器

**功能描述**：
内置视频播放器，支持播放通过视频源解析得到的在线视频流（m3u8/mp4），以及 B站视频。

**播放器功能**：
- 播放/暂停
- 进度条拖拽
- 全屏/退出全屏
- 音量调节
- 亮度调节（可选）
- 倍速播放（0.5x/1x/1.25x/1.5x/2x）
- 加载中状态提示
- 播放出错时的友好提示 + 重试/切换源

**降级方案**：
- 如果直接解析播放失败 → 回退到 WebView 内嵌播放页面
- 如果 B站视频无法内嵌播放 → 提供"跳转到B站App"按钮

**验收标准**：
- [ ] 能成功播放至少 1 种格式的在线视频（m3u8 或 mp4）
- [ ] 播放控制（播放/暂停/进度/全屏/倍速）全部可用
- [ ] 播放失败时不白屏，有明确的错误提示和重试按钮
- [ ] WebView 降级方案可用（直接打开播放网页）
- [ ] 视频加载时有 loading 指示器

---

#### F4：视频源解析引擎（后端）

**功能描述**：
在 PC 端维护一个可扩展的视频源规则库。Agent 或 API 根据电影名搜索各个视频源，解析出可直接播放的视频流地址，返回给手机端。

**核心能力**：
- 根据电影名/关键词搜索视频源
- 解析视频源网页，提取可播放的视频流 URL
- 支持多个视频源（以规则/配置文件形式管理）
- 支持 B站视频搜索 → 获取 bvid → 解析播放地址

**验收标准**：
- [ ] 至少接入 2 个可用的视频源（含 B站）
- [ ] 搜索一部热门电影（如"肖申克的救赎"）能返回至少 1 个可播放的源
- [ ] 返回的视频 URL 能被 Flutter 端 media_kit 成功播放
- [ ] B站搜索"电影名 + 解说"能返回相关视频列表
- [ ] 视频源新增/修改不需要改代码（配置化管理）

---

#### F5：AI Agent 推荐引擎（后端）

**功能描述**：
基于 LangChain 构建的 AI Agent，作为整个系统的"大脑"。它能调用多个工具（TMDB 搜索、评分查询、视频源搜索、B站搜索），综合判断后为用户生成个性化的推荐帖子。

**Agent 具备的工具（Tools）**：
- 搜索 TMDB 电影（按类型/热度/评分/关键词）
- 获取电影详情（简介、演职表、海报 URL）
- 搜索 B站相关视频
- 搜索视频源（查看是否有可播放资源）
- 查询用户偏好与历史

**Agent 工作流**：
1. 读取用户偏好设置（喜欢的类型、不喜欢的类型、历史记录）
2. 调用 TMDB 工具获取候选电影列表
3. 对候选列表进行过滤和排序
4. 为每部推荐电影生成一句个性化推荐语
5. 查询每部电影是否有可用视频源和 B站解说
6. 组装成帖子数据返回

**验收标准**：
- [ ] Agent 能根据"喜欢科幻"的偏好推荐出科幻类电影，不推恐怖片
- [ ] 推荐语是自然语言，读起来像人写的，不是模板套出来的
- [ ] 每次刷新推荐结果有变化（不是固定列表）
- [ ] Agent 调用链可在终端日志中观察到（Tool 调用过程可追溯）
- [ ] 单次推荐请求 10 条帖子的响应时间 < 15 秒

---

#### F6：用户偏好与历史

**功能描述**：
用户可以设置自己的观影偏好，App 记录观影历史。这些数据作为 Agent 推荐的输入依据。

**包含内容**：
- 偏好设置页面：选择喜欢/不喜欢的电影类型（多选标签）
- 可选：输入自由文字描述口味（如"最近想看轻松搞笑的"）
- 观影历史：自动记录点击过详情页的电影、播放过的电影
- 偏好数据持久化存储

**验收标准**：
- [ ] 偏好设置页面可选择至少 10 种电影类型
- [ ] 设置保存后，下次打开 App 偏好仍在
- [ ] 观影历史页面能展示访问过的电影列表
- [ ] 修改偏好后，首页推荐内容有明显变化

---

#### F7：PC-手机连接

**功能描述**：
手机 App 通过局域网连接到 PC 端 FastAPI 服务。用户在 App 设置页输入 PC 的 IP 地址和端口，建立连接。

**包含内容**：
- 设置页面输入 PC 地址（如 192.168.1.100:8000）
- 连接状态指示（已连接/未连接/连接失败）
- 连接测试按钮（ping 后端 health 接口）
- 连接成功后自动开始拉取推荐数据

**验收标准**：
- [ ] 输入正确 IP:Port 后能成功连接
- [ ] 连接状态有明确的 UI 反馈（图标/文字/颜色）
- [ ] 连接失败有友好的错误提示（如"PC端服务未启动"）
- [ ] 断开连接后再重连不需要重启 App

### 🟡 扩展功能（有余力再做，每个都是加分项）

---

#### F8：Micro Design 动态海报

**功能描述**：
Agent 不仅推荐电影，还为每部推荐电影生成一张精心设计的"Micro Design 海报"。海报风格根据电影类型自动匹配（科幻→暗色赛博风、文艺→暖色水彩风、动作→高对比热血风...）。这些海报不是 TMDB 的原版海报，而是 AI + 模板生成的专属设计。

**验收标准**：
- [ ] 至少 3 种不同风格的海报模板
- [ ] 海报包含：电影名、评分、推荐语、海报底图，排版美观
- [ ] 不同类型的电影自动匹配不同风格

---

#### F9：AI 对话交互

**功能描述**：
App 内有一个对话页面，用户可以用自然语言和 Agent 聊天互动。比如"推荐一部像星际穿越一样的电影"、"我今天心情不好想看点治愈的"、"诺兰还有什么好电影"。Agent 理解意图后给出推荐。

**验收标准**：
- [ ] 对话界面类似聊天 UI（用户消息 + Agent 回复）
- [ ] Agent 回复中包含推荐的电影，可直接点击跳转到详情页
- [ ] 对话有 streaming 效果（逐字输出）或至少有"正在思考"的加载态
- [ ] Agent 能理解模糊的自然语言请求（不需要精确关键词）

---

#### F10：网盘资源解析

**功能描述**：
用户输入阿里云盘/夸克网盘/百度网盘的分享链接，后端解析出视频文件列表，可以选择在线播放（不下载到本地）。

**验收标准**：
- [ ] 支持至少 1 种网盘的链接解析
- [ ] 解析后能展示文件列表（文件名、大小）
- [ ] 选择文件后能在 App 内播放

---

#### F11：PC 同步播放控制

**功能描述**：
手机作为遥控器，控制 PC 端播放电影。PC 端用本地播放器（如 mpv/VLC）播放视频，手机端控制播放/暂停/进度/音量。

**验收标准**：
- [ ] 手机发出播放指令后 PC 端 1 秒内响应
- [ ] 基本控制可用：播放/暂停/进度拖拽

---

#### F12：影视资讯推送

**功能描述**：
Agent 定时（或手动触发）从网上搜集最新影视资讯（新片上映、评分变动、热点话题），整理成资讯帖子推送到手机 App 的"资讯"Tab。

**验收标准**：
- [ ] 资讯 Tab 页面有内容展示
- [ ] 每条资讯包含标题、摘要、来源链接
- [ ] 至少展示 5 条有实际内容的资讯

## 四、三人分工（功能模块制，每人小全栈）

> 核心原则：**一人一个功能域，从后端到前端全包，谁也不等谁。**

### Day 1 全员共建（半天完成）

**共建内容**：
- Flutter 项目初始化（空壳 + 底部导航 + 路由框架 + 主题色 + 网络请求封装）

**共享代码约定**：

- 各自功能代码放在各自的模块目录下，不交叉修改

### 协作边界说明

```
三人的代码在各自模块目录内，通过 API 接口和数据模型松耦合连接：

B 的帖子流 → 点击卡片 → 跳转到 B 自己的详情页 → 详情页里的"播放"按钮
  → 调用 A 的视频源 API → 跳转到 A 的播放器页面

B 的帖子卡片 → 海报图 URL 指向 C 的海报生成 API → C 返回 Micro Design 海报图

C 的对话页 → Agent 推荐了一部电影 → 点击 → 跳转到 B 的详情页

连接关系是"路由跳转 + API URL"，不是代码级依赖，各自独立开发无阻塞。
```

**模块间的接口契约（Day 1 定好就行）**：

```
// B 暴露给 A 和 C 的跳转：
路由：/movie-detail/:movieId  → B 的详情页

// A 暴露给 B 的接口：
GET /api/sources/search?movie_name=xxx    → 返回视频源列表
GET /api/sources/parse?source_id=xxx      → 返回播放 URL
路由：/player?url=xxx&title=xxx           → A 的播放器页面

// C 暴露给 B 的接口：
GET /api/poster/{movie_id}                → 返回 Micro Design 海报图 URL

// B 暴露给 C 的接口：
GET /api/movie/{movie_id}                 → 返回电影详情数据（C的对话推荐结果可用）
```

## 七、答辩展示亮点

1. **AI Agent 驱动**：不是静态的电影列表，是 AI 实时理解偏好后生成的个性化推荐
2. **Micro Design**：每张推荐海报都是动态生成的，不同电影不同风格，有设计感
3. **PC-Mobile 分布式架构**：PC 做算力中心 + 手机做交互终端，体现系统设计能力
4. **多源聚合**：TMDB + B站 + 第三方视频源，一站式找片和观影
5. **自然语言交互**：和 AI 聊天就能找到想看的电影
6. **技术栈前沿**：Flutter 跨平台 + FastAPI 异步 + LangChain Agent，全栈 + AI
